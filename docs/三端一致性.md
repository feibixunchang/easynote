# 三端一致性说明（开发者向）

> 本文件说明「简易笔记」三端前端的关系、修改铁律与本次数据安全加固清单。
> 相关工具：`tools/parity-check.sh`

## 一、三端文件对应关系

| 端 | 入口 | 前端逻辑 | 说明 |
|---|---|---|---|
| 桌面端（Electron: Win/macOS/Linux） | `index.html` | **`app.js`** | 另有 `main.js`（主进程）、`preload.js`（IPC）、`updater.js`（更新） |
| 移动端（Capacitor: iOS/Android） | `mobile/www/index.html` | **`mobile/www/app.js`** | 由 `mobile/install-ios.sh` 装到手机 |
| 网页版（服务器托管 / PWA） | `server/web/index.html` | **`server/web/app.js`** | 由 `server/deploy-web.sh` 发到服务器 |

- `server/web/app.js` **应当与根目录 `app.js` 完全一致**（网页版是桌面端前端的一份构建产物）。
  同步方式：`cp app.js server/web/app.js`
- `mobile/www/app.js` 历史上与桌面端**分叉**（大量平台差异），属已知技术债，见第四节。

## 二、修改铁律（重要）

**凡是涉及「同步协议 / 数据结构 / 冲突处理」的改动，必须三端同改**，否则会出现
「桌面修好了、手机还在丢数据」这类问题。判定标准：改动是否触及下面这些跨端契约——

- 存储键：`SINCE_KEY` / `PUSHED_KEY` / `PURGE_KEY` / `TOTAL_KEY`
- 接口：`/api/notes/sync`、`/api/notes/purge`、`/api/notes?since=`
- 核心函数：`mergeNotes`、`applySyncResponse`、`notesToPush`、`markPushedAfterRound`、
  `recoverFromShrink`、`filterPurged`、`purgeOnServer`、`isValidNoteId`、`makeConflictCopy`

改完请务必运行：

```bash
bash tools/parity-check.sh
```

它会检查上述契约是否三端齐全、网页版与桌面端是否一致；缺一端就**非 0 退出**（可挂到 CI）。

## 三、本次数据安全加固清单

### 服务端 `server/server.js`（版本号 → 1.4.0）

1. **原子写 + `.bak` 备份**：`writeFileAtomic()` 先写 `.tmp` 再 `rename`，并在覆盖前留 `.bak`。
   原先直接 `fs.writeFileSync` 覆盖，写到一半被杀/断电会把 JSON 截断 → 该用户整库笔记读不出来。
   读取时 `readJsonWithBak()` 在主文件损坏时自动回退 `.bak`。
2. **墓碑防"复活"**：同步时只有当 `incoming.modifiedDate > 墓碑时间`（真正的撤销删除）才允许
   清除墓碑；否则拒绝写入并把该 id 放回 `removed`。避免 A 设备永久删除后，B 设备在收到墓碑前
   把旧副本推上来导致"已删笔记全端复活"。
3. **单调入库时间戳**：`nextStamp()` 保证每次入库时间戳严格递增（同毫秒 +1），游标取
   `lastStamp`。解决"两台设备同毫秒写入导致某设备永久漏同步"的竞态。
4. **脏数据拦截**：笔记 id 白名单校验（`isValidId`，拒绝 `__proto__`/`constructor`/`prototype`
   与非法字符）；对象统一转为无原型字典（`toDict`），避免原型污染。
5. **用户名安全**：注册时拒绝含 `/` `\` `..` 控制字符及危险键名；`userNotesFile()` 增加
   路径落点校验（防止用户名做路径穿越）。

### 客户端（桌面 `app.js` + 移动 `mobile/www/app.js` + 网页同步）

6. **冲突副本**：两台设备同时改同一篇笔记时，服务端版本（后写）胜出的同时，把"本机未同步
   成功的版本"另存为独立笔记「⚠ 冲突副本（本机版本 …）」，并 toast 提示。不再静默丢改动。
7. **入站 id 校验**：`isValidNoteId()`，丢弃非法 id，防原型污染导致笔记"消失"。
8. **被拒推送自愈**：服务端因墓碑拒绝的 id 会出现在 `removed` 里，客户端据此清掉本地副本并记入墓碑。

### 桌面主进程 `main.js`

9. `open-external` 的 `easynote-file:` 分支**只放行图片扩展名**（此前可打开任意本地文件/程序）。

### 版本号

- 桌面端 `1.2.21 → 1.2.22`
- 移动端 `1.0.12 → 1.0.13`（`mobile/package.json` 与 `mobile/www/app.js` 的 `APP_VERSION` 必须一致，
  否则 `install-ios.sh` 的同步校验会失败）

## 四、遗留技术债与推进建议

现状（`tools/parity-check.sh` 可复现）：

```
桌面端  3085 行
移动端  2566 行   （桌面独有 2047 行 / 移动独有 1528 行）
网页版  3085 行   （= 桌面端）
```

**同步 / 协议相关逻辑已强制对齐**，但 UI 与平台差异仍是两套代码。彻底解决建议分三步：

1. **抽出共享核心**：把 `state / 存储 / 同步 / 冲突 / 历史快照` 抽成 `shared/core.js`
   （用 `<script>` 在各端 index.html 中先于 `app.js` 引入），`app.js` 只保留 UI。
2. **平台适配层**：把「导入导出 / 剪贴板 / 文件选择 / 更新 / 通知」等归纳为 `platform.js`
   接口，各端提供实现（Electron / Capacitor / 浏览器）。
3. **产物化**：`mobile/www` 与 `server/web` 一律由脚本从共享源码生成，禁止手工复制；
   在 CI 里跑 `tools/parity-check.sh` 阻断分叉。

> 第 1、2 步属于较大重构，建议单独排期、每步都跑一次真机回归（iOS 侧载 + 桌面打包）。
